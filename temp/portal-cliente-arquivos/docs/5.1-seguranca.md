# 5.1 Grupo 1 — Segurança de APIs e controle de acesso

## Como foi implementado
- **Autenticação:** API com HTTP Basic (stateless) e painel com login por formulário, sessão, logout e CSRF (`SecurityConfig`, `LoginController`). Senha com BCrypt. API sem credencial → 401; painel → redireciona para `/login`.
- **Autorização por papel (RBAC):** regras por rota em `SecurityConfig` (ADMIN, TECNICO, CLIENTE). Sem papel adequado → 403.
- **Autorização por objeto:** `AutorizacaoChamado` (dono / técnico atribuído / admin), chamada em `ChamadoService.buscarEntity`. Objeto alheio → 404 (não revela existência).
- **Validação de entrada:** Bean Validation nos DTOs; senha 8–72 caracteres; página limitada a 50.
- **Contrato REST:** `clienteId` (cliente) e `autor` (comentário) deixam de ser confiados ao corpo; senha só existe nos *Request* e nunca nos *Response*.
- **Respostas padronizadas:** `GlobalExceptionHandler` + `SecurityConfig` devolvem `ErroResposta` (400, 401, 403, 404, 409, 500) sem stack trace.
- **Logs/config:** `show-sql=false`, H2 console removido, `toString` dos requests sem senha, mensagem de e-mail duplicado sem ecoar o e-mail.

## Fluxo atual × proposto
| Aspecto | Antes | Depois |
|---|---|---|
| Autenticação | nenhuma | API: HTTP Basic; painel: login por formulário; BCrypt |
| Autorização | nenhuma | RBAC por rota + dono/atribuído no service |
| Dono do chamado | `clienteId` do corpo/query | usuário autenticado |
| Autor do comentário | texto livre | usuário autenticado |
| Listagem de chamados | todos para qualquer um | filtrada por papel |
| Erros | 400/404/409 | + 401/403, 500 genérico, sem stack trace |
| Console/SQL | H2 console e `show-sql` ligados | desligados |
| Regra de negócio | `existsByStatus(FECHADO)` global bloqueava toda atribuição | checa o status do próprio chamado |

Fluxo novo: requisição → `SecurityFilterChain` (identidade e papel) → controller → service (`AutorizacaoChamado`) → repository → DTO → resposta padronizada.

## Riscos OWASP API Security Top 10 tratados
| Risco | Mitigação |
|---|---|
| API1 BOLA | `AutorizacaoChamado`, filtros por token, 404 em objeto alheio |
| API2 Autenticação quebrada | BCrypt, 401 padronizado, mensagem de login genérica |
| API3 Propriedades | `clienteId` e `autor` não vêm do cliente; senha fora dos Response |
| API4 Consumo de recursos | `max-page-size=50` (não há rate limit) |
| API5 Função sem restrição | RBAC por rota; DELETE/atribuir só ADMIN |
| API8 Configuração | H2 console off, `show-sql` off, erros sem stack trace |

## Limitações conhecidas
- CSRF está desabilitado apenas na API (stateless com Basic); o painel usa sessão com CSRF ligado.
- Sem rate limit no login/cadastro; sem bloqueio de conta.
- `POST /clientes` público permite distinguir e-mail já cadastrado (409).
